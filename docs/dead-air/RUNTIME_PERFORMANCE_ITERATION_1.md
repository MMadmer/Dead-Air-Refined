# Первая итерация runtime-оптимизации

## Основание

Профиль всех 32 локаций на R4 показал, что наиболее тяжёлые открытые сцены
упираются в CPU-подготовку рендера и driver submission. В подтверждённых горячих
путях находятся `CBackend::set_Textures`, `R_dsgraph_structure::insert_static`,
`R_dsgraph_structure::render_graph` и `CPortalTraverser::traverse_sector`.

Отдельно полный прогон записал 1 994 одинаковых предупреждения об отсутствии
ранга `wpn_m249`. Они создаются из AI item-selection path повторным линейным
поиском `get_rank` и синхронной записью в лог.

## Неприкосновенные ограничения

- Не менять качество изображения, дальность, LOD, culling result и порядок
  отрисовки.
- Не менять игровую механику, состав мира, частоту симуляции и ALife policy.
- Не менять форматы сохранений, Lua API, экспортируемый ABI и загрузку аддонов.
- Не удерживать ресурсы выгруженной локации.
- Не исполнять Lua конкурентно и не добавлять конкурентную запись в игровые
  объекты.
- Сохранять `Release|x64` с `/WX`: ноль предупреждений и ноль ошибок.
- Удалять каждую правку, которая не даёт воспроизводимого выигрыша либо вызывает
  визуальную, gameplay, compatibility или memory-регрессию.

## Пачка первой итерации

### 1. Повторная привязка texture-list

Для DX11 вводится общий монотонный epoch изменения array slice. Каждый backend
запоминает увиденный epoch в существующем padding-поле, поэтому layout и ABI
`CBackend` не меняются. При повторном `set_Textures` неизменный epoch позволяет
не обходить весь список текстур. При изменении любого slice сохраняется текущий
полный проверочный путь и привязываются все изменившиеся SRV.

### 2. Поиск pass-bucket в dsgraph

Static и dynamic insertion запоминают последний `SPass` и найденный bucket для
каждой пары priority/pass. Последовательные визуалы одного материала больше не
выполняют повторный поиск в `xr_fixed_map`. Cache сбрасывается вместе с graph и
после каждого `render_graph`, поэтому указатель не переживает очистку map.

Порядок элементов, SSA, сортировки, shader pass и draw calls не меняется.

### 3. Portal traversal

До нормализации направления применяется математически безопасная верхняя
граница SSA. Если `radius^2 / distance^2` уже ниже discard threshold, множитель
`abs(dot)` не может сделать портал видимым. В этом случае исключаются `sqrt`,
деление и dot product без изменения результата culling.

### 4. Кэш ранга предметов

Результат исходного поиска `strstr` кэшируется отдельно для каждого worker
thread. Инициализация строк рангов выполняется один раз. Неизвестный section
сохраняет прежний fallback rank `0`, но глобальное предупреждение записывается
только один раз для section.

Сами списки рангов и результат сравнения оружия не меняются.

## Не входят в первую итерацию

- Перенос или изменение Lua dispatcher/GC: предыдущий A/B не подтвердил
  ускорение, а sampling line `bind_stalker` является Lua/native boundary.
- Изменение количества ALife-объектов: рост во время тура ещё не отделён от
  законного persistent world state.
- Постоянный decompression cache: он нарушит запрет удерживать ресурсы
  выгруженной локации и может увеличить уже наблюдаемый memory high-water.
- Изменение OPCODE tree build: профиль не отделяет level-load построение от
  steady frame, а level CFORM уже имеет сериализованный tree cache.
- Отключение SSAO, volumetric, деталей, частиц, солнца или tessellation: A/B не
  подтвердил достаточного выигрыша и такое изменение снизит качество.

Эти пункты требуют отдельной атрибуции или измеримого A/B до изменения кода.

## Проверка после завершения всей пачки

Промежуточные игровые и производительные тесты до завершения кода не
выполняются. После окончания первой итерации последовательно выполняются:

1. `git diff --check` и статическая проверка затронутых контрактов.
2. Полная чистая и повторная `Release|x64` сборка с `/WX`.
3. Развёртывание полного runtime-набора с проверкой SHA-256.
4. Загрузка существующего сохранения, переход уровня, save/reload и активный
   soak не менее пяти минут.
5. Проверка лога на fatal, assertion, access violation, Lua error и новые
   предупреждения.
6. Same-scene A/B baseline/candidate на основном Windows Desktop; изменения
   меньше одного процента считаются шумом.
7. Проверка изображения и UI; любая видимая регрессия отменяет render-правку.
8. Проверка private memory, handles, threads и отсутствия процессов игры,
   сборки, профайлера и отладчика после QA.

## Результат первой итерации

- `Release|x64 -Clean`: успешно, 0 предупреждений, 0 ошибок.
- Повторная `Release|x64`: успешно, 0 предупреждений, 0 ошибок.
- Развёрнут 41 runtime-файл; SHA-256 source/deployed совпал для каждого файла.
- Загружено существующее сохранение, выполнены переходы
  `l08u_brainlab/l01_escape -> l05_bar -> l01_escape`, godmode оставался
  включённым.
- Создано и повторно загружено сохранение `runtime_iter1_qa`.
- Пятиминутный soak на `l01_escape` завершился штатным `KERNEL:QUIT`; fatal,
  assertion, access violation и Lua runtime error от candidate-кода не найдено.
- После финального аудита fast-path `set_slice` дополнительно проверяет
  фактический SRV, чтобы первичная установка slice `-1` не могла быть
  пропущена. Повторная сборка прошла с 0 предупреждений и 0 ошибок; финальный
  30-секундный smoke на `l01_escape` завершился штатно.
- После стабилизации уровня private bytes изменились с 4 164 575 232 до
  4 165 632 000 байт на контрольном интервале. Признака монотонной утечки нет.

Same-save A/B/A выполнялся на `l05_bar`, R4, VSync off, после 15 секунд
прогрева и с 45-секундным окном:

| Build | Frames | Avg, ms | P50, ms | P95, ms | P99, ms | Max, ms |
|---|---:|---:|---:|---:|---:|---:|
| Candidate A1 | 5 916 | 7.607 | 7.265 | 10.644 | 17.950 | 25.594 |
| Baseline B | 5 331 | 8.442 | 8.100 | 11.048 | 20.535 | 31.199 |
| Candidate A2 | 8 060 | 5.583 | 5.304 | 7.575 | 13.154 | 20.875 |

Оба candidate-прогона быстрее baseline: A1 улучшил average frame time на
9.9%, P95 на 3.7% и P99 на 12.6%; A2 — соответственно на 33.9%, 31.4% и
35.9%. Разброс между A1 и A2 показывает влияние динамической сцены, однако
направление результата одинаково по всем метрикам и запас выше обязательного
порога 1%. Вся пачка первой итерации оставлена.

Артефакты QA находятся в
`_analysis/runtime-opt-iteration1-20260801`: A/B/A-логи, smoke/soak-лог и CSV
проверки SHA-256.
