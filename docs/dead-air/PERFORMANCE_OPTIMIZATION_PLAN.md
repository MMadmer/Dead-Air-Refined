# Оптимизация производительности Dead Air x64

## Ограничения

- Не менять качество изображения и игровые правила.
- Не менять формат сохранений, Lua API и ABI экспортируемых классов.
- Оставлять только правки с воспроизводимым выигрышем.
- Удалять экспериментальные правки при регрессии или отсутствии прироста.

## Подтверждённые горячие пути и правки

### Массовое удаление объектов после загрузки

- До правки один кадр занимал 257,1 мс, из них 241,7 мс приходилось на
  уничтожение 302 объектов.
- Основная причина — более 526 тысяч вызовов `net_Relcase`: каждый удаляемый
  объект сообщался всем активным и спящим объектам, включая Lua-binder с
  унаследованным пустым обработчиком.
- Проверка наличия script binder перенесена перед дорогим `smart_cast`.
- Тип Lua-обработчика проверяется не чаще одного раза за кадр. Пустые Lua-функции
  и унаследованный пустой native fallback не вызываются, а реальные
  переопределения модов продолжают работать.
- Порядок `net_Relcase`, callback и уничтожения объектов не изменён. Базовые
  игровые классы, формат сохранений и Lua API не расширялись.
- На том же сценарии полная фаза сократилась до 20,632 мс, то есть примерно на
  91,5%. Измерительная обвязка после подтверждения результата удалена.
- Эксперимент с переносом уничтожения на последующие кадры давал фатальную
  ошибку и задерживал освобождение объектов на 22 кадра. Он полностью удалён.

### ALife switch update

- Параметр `process_time = 900` задаётся в микросекундах, но использовался как
  значение в секундах. Фактическое ограничение работы ALife не действовало.
- Значение теперь корректно переводится в секунды с сохранением исходного
  коэффициента монстров: штатный бюджет равен 810 микросекундам.
- Обработка не пропускается: незавершённый обход продолжается последующими
  обновлениями.

### GOAP-планировщик NPC

- При неудачном построении плана движок безусловно формировал полный
  диагностический дамп состояний, хотя логирование конкретного планировщика
  было выключено.
- Дамп теперь создаётся только при включённом `m_use_log`.
- Повторяемый участок снизился примерно с 5–10 до 2–3 мс; игровые условия,
  операторы и частота обновления AI не менялись.

### Секторизация рендера

- Сектор камеры ошибочно инвалидировался сравнением сохранённого направления
  с текущей позицией.
- Сектора камеры, динамических объектов и источников света теперь
  пересчитываются только при изменении позиции или установленном
  `STYPEFLAG_INVALIDSECTOR`.
- Среднее время `Calculate` снизилось с 17,5 до 11,8 мкс, а повторный поиск
  сектора объектов — с 4,3 мкс до значений ниже точности замера.
- На одинаковой сцене медиана кадра улучшилась с 7,307 до 6,679 мс
  (около 8,6%), p95 — с 11,456 до 10,319 мс (около 9,9%).
- Среднее ожидание основной задачи culling снизилось с 2,009 до 0,813 мс
  (около 59,5%).
- Сравнение полных кадров не выявило пропавшей геометрии или изменения
  качества изображения.

## Проанализировано без изменения кода

- Lua GC действительно даёт редкие тяжёлые проходы. Плотные индексы userdata
  ускоряли синтетический проход GC примерно на 67%, но два независимых
  варианта падали на реальной загрузке сохранения. Эксперимент полностью
  удалён, LuaJIT возвращён к стабильной реализации.
- Перестройка scheduler heap не оправдана: профиль показал затраты внутри
  обновляемых объектов, а не в операциях очереди.
- Изменение частоты AI, скриптовых callback и физики не применялось, поскольку
  это меняет игровой процесс.
- Редкие пики physics и network не воспроизводились систематически.
- Микрооптимизации ради предупреждений компилятора не применялись.

## Проверка

1. Собрать полную конфигурацию `Release|x64` с очисткой промежуточных файлов.
2. Повторно собрать без очистки и подтвердить отсутствие ошибок.
3. Скопировать весь набор runtime-бинарников в корень игры и сравнить SHA-256.
4. Загрузить контрольное сохранение на скрытом рабочем столе.
5. Продержать локацию активной не менее пяти минут.
6. Проверить быстрое сохранение и последующую загрузку.
7. Проверить лог на fatal, assertion и новые ошибки.
8. Убедиться, что после теста не осталось процессов игры или сборки.
